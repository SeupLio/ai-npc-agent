# 边界与不足 · 证据单

> **一句话**：`235/235` 是**回归基线**，不是能力上限。它证明的是「护栏没坏」，
> 不是「NPC 很聪明」。面试时**先自己说清这句**，比等对方问出来强得多。
>
> 这份文档只做一件事：把每一处边界的**实测数字 + 出处 + 追问怎么答**列在一起。
>
> **规则**：只写量过的。没量过的单独列在第 5 节，并写清为什么没量。
> 这条规则是硬的 —— 这个项目已经因为"写了没量过的数"栽过几次，
> 每次都是同一个形状：**手抄的数字 + 没有护栏 = 迟早变成假话**。

## 1. 先回答那个最扎人的问题

**「235/235 是不是太好了？」—— 是太好了，好到几乎没有信息量。**

三条**互相独立**的证据，全部离线可复现（0 次模型调用）：

| # | 实验 | 数字 | 它说明什么 |
|---|---|---|---|
| 1 | 把**记忆整个模块**拿掉（消融 `none` 臂） | **229/235 = 97.4%** | 框架里最大的那个模块，只值 **6 条**用例 |
| 2 | 四种检索策略**互相比** | 全部 **235/235**，Δ=**0.000** | 评测**分辨不出**检索策略的差别 |
| 3 | 把计划按比例砍掉（剂量-反应） | 砍 **10%** → **223/235** | 报警线画在 **10%**，不是"任何扰动" |

第 2 条尤其值得主动讲：**它是一次"阴性结果"，而我把它写进了报告。**
四种策略（`hybrid` / `recency` / `lexical` / `importance`）在 235 条上**一模一样**。
一个只想让数字好看的人会删掉这条；它恰恰是"评测可信"的证据 ——
因为**一个分不清优劣的评测，它的满分也不该被当成"优"**。

出处：[`docs/ablation.html`](ablation.html)（记忆消融）、
[`docs/resolution.html`](resolution.html)（剂量-反应）、
[`docs/sensitivity.html`](sensitivity.html)（变异测试）。

## 3. ⭐ 新增：剂量-反应曲线（`resolution.html`）

### 为什么原来的变异测试不够

`sensitivity.html` 是**二值**的：注入缺陷 → 抓到没有 → **6/6**。
这个读数看着像"评测很灵敏"，但它其实**什么也没说** —— **只要掉一个点就算抓到**。

> 一个只能发现「整个模块被拔掉」的评测，
> 和一个能发现「计划少走了一步」的评测，
> 在 **6/6** 这个读数上**长得一模一样**。

### 做法与结果

把每个计划里的步骤按比例 `k` 丢掉（确定性均匀抽样，不是随机），测通过率：

| 丢掉计划比例 k | 通过 | 通过率 | Δ |
|---|---|---|---|
| 0.0 | 235/235 | 1.0000 | — |
| **0.1** | **223/235** | **0.9489** | **−0.0511** ← 开始掉分 |
| 0.2 | 209/235 | 0.8894 | −0.1106 |
| 0.3 | 181/235 | 0.7702 | −0.2298 |
| 0.5 | 166/235 | 0.7064 | −0.2936 |
| 0.7 ~ 1.0 | 139/235 | 0.5915 | −0.4085（平台） |

**检出阈值 = 10%。**

两个**自洽性检验**（这是这份报告最硬的地方）：

1. **k=1.0 → 0.5915**，而独立的 `planning_disabled` 变异是 **0.591**。
   两条完全不同的实现路径给出同一个数 ⇒ 「丢光计划」和「不做规划」是同一个口径。
2. **k≥0.7 出现平台** —— 再砍也不会更差，因为已经没有用例能完成目标了。

### ⭐ 最重要的发现：4/6 个维度**恒为 1.000**

整条曲线上，`memory` / `persona` / `safety` / `turn_taking` **一次都没动过** ——
哪怕把规划**整个拔掉**（k=1.0，NPC 完全不会推进目标、不调任何工具）。

| 维度 | k=0 | k=1.0（无规划） |
|---|---|---|
| `task` | 1.000 | **0.591** |
| `tools` | 1.000 | **0.604** |
| `memory` | 1.000 | **1.000** |
| `persona` | 1.000 | **1.000** |
| `safety` | 1.000 | **1.000** |
| `turn_taking` | 1.000 | **1.000** |

这比"覆盖率 52%"更硬：

* 覆盖率不足说的是「**可能**没测到」；
* 恒为 1.000 说的是「**确实**没测到」。

**所以这 4 个维度的分数，不能拿来当「规划没问题」的证据。**
它们各有各的靶子（记忆检索、人设边界、越权拦截、发言权调度），
但**它们测不到规划** —— 这是它们的分工，不是它们的功劳。

### ⚠️ 这条曲线给的是**下界**

剂量是**均匀**丢步，而真实模型的退化更可能集中在**难的那几步**上
（最后那个改世界状态的步骤）。所以真实退化会被评测**更早**看见。
换句话说：**10% 是最不利情形下的灵敏度**，不是估计值。

## 4. 权威测试：**没有**，而且我说得清为什么

**没有跑过 LOCOMO / LongMemEval 之类的公开基准。**
原因是当时环境**拿不到数据集**，仓库里只有适配器和 6 条内置样例。

**所以：不能把这里的数字说成"公开基准上的成绩"。** 这句话写在 README 第 1 条局限里。

那为什么还是可信？因为这套数字的定位**本来就不是**"能力证明"，而是**回归护栏**：

| 它**能**回答 | 它**不能**回答 |
|---|---|
| 改了代码，框架逻辑有没有被弄坏 | 这个 Agent 比别人的聪明吗 |
| 护栏还在不在工作 | 换个模型还能不能行 |
| 某个模块的**净收益**有多大 | 在真实玩家手里的体验 |

**追问"为什么不接公开基准"时**，答：接得上 —— `eval/` 里已经有 LongMemEval 的适配器，
缺的是数据集和一次跑批。**没做，所以不说。** 这比"跑了但结果一般所以不写"要诚实。

## 5. 边界清单

### 5.1 已量过（每条都有数字）

| 边界 | 实测 | 出处 |
|---|---|---|
| 离线满分**不是模型能力** | 离线路径**0 次模型调用**，分数只反映框架逻辑 | `cli eval` |
| 真实模型读数**已饱和** | 227/228 = **99.6%**（228 条版本，用例集后来长到 235） | `batch_model.html` |
| 把规划交给模型**会掉分** | **88.6%**；真让模型规划的那 130 条 **85.4%** | `batch_planner.html` |
| **端点不稳是测 LLM 规划的最大障碍** | 整臂 **48%** 至少回落一次（回落**现在可见**，但端点仍不稳） | README 局限 5 |
| 重试**只吃得掉抖动** | `retries=1` 5 次调用失败 1 次；`retries=3` 6 次调用失败 0 次。⚠️ **样本只有 1 次重试事件** | README 局限 5 |
| **裁判判决不可复现** | `temperature=0`、prompt 逐字节相同，`grounded` 有 **22.2%（2/9）** 概率给出相反结论 | README 局限 11 |
| **六维评测看不见"复读"** | 10 轮对话 **62%** 的台词逐字重复（44 句里 27 句），**同时**六维全 1.000 | README 局限 10 |
| 离线启发式**撑不住长对话** | 20 轮后复读率爬到 **20%~40%**（下界 `(轮数−词汇量)/轮数`）；10 轮内 0% | README 局限 9 |
| **反思曾把"守规矩"记成"有毛病"** | 457 条反思里 **139 条（30.4%）是假教训**；最高频那条出现 **122 次** | README 局限 12 |
| 同一个假象**有 5 个出口** | 记忆 / 评测转写 / 控制台 / 自测网页 / 规划状态机。规划那处 **228 个 step 被误标 `failed`**、`replan` **309 → 93** | README 局限 13–15 |
| **"无害"可能是借来的** | 两份实现巧合一致才无害；只改一处 → `tell_fact` 失败 **0 → 25** 次，**分数仍 235/235** | README 局限 16 |
| 真实 Minecraft 服务端**未接入默认路径** | 桥脚本 + 协议验证都在，缺服务端环境；默认走进程内 `LocalWorldClient` | README 局限 7 |

### 5.2 ⭐ 一个值得主动讲的口径故事：**122 和 98 都对**

这个项目里有两个看着矛盾的覆盖率数字，**两个都是对的**：

| 口径 | 数字 | 定义 |
|---|---|---|
| 「**断言了世界状态**」 | **122/235 = 51.9%** | `expect` 里有任意世界状态键 |
| 「**真的能对某个目标完成变绿**」 | **98/235 = 41.7%** | 逐目标检查：目标完成时这条用例会不会变绿 |

差 **24 条**，而且**恰好等于** `no_flags` 断言的条数 ——
`no_flags` 是「这个标记**不许**被置上」的**否定式**断言：
它是一句关于世界的话（所以算"断言了世界状态"），
但它**永远不会因为某个目标完成而变绿**（所以不算"覆盖了目标"）。

**这个故事的用法**：面试官问"你的数字靠谱吗"，答"我踩过一次两个数看着打架的坑，
最后发现是两个口径，差额能**精确对上**一个键 —— 所以现在我引用任何比例都先说口径"。

## 6. 未量过（明确标注，不装懂）

| 没量过的事 | 为什么没量 | 如果要做 |
|---|---|---|
| 公开基准（LongMemEval / LOCOMO） | 当时拿不到数据集 | 适配器已在，补数据集 + 一次跑批 |
| **真人玩家体验** | 没有真人被试 | 需要用户研究，不是工程能替代的 |
| **裁判与人工标注的一致性** | 没有人工标注集 | 标注 200 条 → 算 kappa。**在那之前，"多数票更准"没被验证** |
| **`grounded` 裁判的噪声底** | 只测了 9 条重复采样 | 扩大重复采样，把 22% 收成区间 |
| **规划敏感度 10% 是不是通用** | 只测了"均匀丢步"这一种退化路径 | 换别的退化路径（丢难步骤 / 错序 / 错参数）各测一遍 |
| 长对话（>20 轮）的表现 | 离线模板池撑不住，模型跑批又贵 | 接模型跑 50 轮 |
| 多 NPC 场景的规模上限 | 最多只有 **2 个 NPC**（`duet`）。⚠️ 别把 `icebreaker` 的 **3 个玩家**记成 3 个 NPC —— 那是**玩家**数 | 加 NPC 数量做压力测试 |
| 端到端延迟 / 成本 | 只记了总耗时（4999s / 228 条） | 分阶段打点 |

**这一节的用法**：面试官问"你觉得哪里还没做好"，**直接背这张表**。
它比"我觉得还需要优化性能"具体一百倍 —— 而且**每一条都说了为什么没做**。

## 7. 追问速答

| 追问 | 怎么答 |
|---|---|
| **"235/235 是不是自欺欺人？"** | 是**框架逻辑**的满分，不是模型能力的满分 —— 离线路径一次模型都没调用。而且我做了三层实验证明它不是"护栏从不报警"：变异测试 6/6、剂量-反应阈值 10%、记忆消融只值 6 条。真实的模型读数在 `batch_model.html`，**已经饱和**，我也写清楚了。 |
| **"满分还能说明什么？"** | 说明**护栏在工作**。它的价值是回归：改代码弄坏了什么，它会红。要重新有区分度，得加更难的用例 —— 这是我在第 6 节列的第一项待办。 |
| **"你怎么知道你的评测有用？"** | 三层：① 注入 6 个已知缺陷，6/6 被抓；② 把剂量做连续，量出**报警线在 10%**；③ **把修好的根因放回去**，看回归测试会不会红（`scripts/verify_dialogue_coherence.py`，两个变异体逐字复现了用户报的症状）。 |
| **"哪个维度最弱？"** | `retrieval_disabled` 只让通过率掉到 **97.4%** —— 记忆的**检索侧**最薄。其次是 `turn_taking` 的部分场景。两者都在 `sensitivity.html` 里标着。 |
| **"为什么不用 LangChain？"** | 要的是**可控性**：什么时候不说话、什么话不能说、失败了怎么归因 —— 框架给不了。而且评测要可复现 ⇒ 我需要一条**确定性的离线路径**，框架里没有。 |
| **"最大的技术短板？"** | ① **端点稳定性**（48% 回落）—— 重试只吃得掉抖动；② **评测覆盖不均** —— 4/6 个维度对规划**恒为 1.000**；③ **裁判噪声**（22% 反向判决）—— 没有人工标注。 |
| **"你从这次经历学到最重要的一件事？"** | **「护栏写了」和「护栏在跑」是两件事。** 我有一条护栏写了、也有反向测试，但被环境变量挡在默认之外，于是它守护的报告过期了两次。判据现在是一句话：**问「默认跑批里，有没有哪一条会在它坏掉时变红？」** 答不上来就等于没有护栏。 |
