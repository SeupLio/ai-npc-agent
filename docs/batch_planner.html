怎么读这张表

  • 先看"模型调用"，再看通过率。调用次数为 0 的 100% 和 调用几千次的 100% 是两件完全不同的事，前者衡量的是框架的确定性逻辑。
  • 模板兜底：模型调用失败后框架会退回离线模板， 那条用例的台词就不是模型写的了。比例高的时候通过率会虚高。
  • 加速比是量出来的：串行估计 / 实际墙钟， 分子分母都只用本次实际执行的用例。明显低于并发数说明瓶颈在端点排队。
  • 诚实声明：228 条全部是自建用例， 不是 AgentBench / τ-bench 这类公开榜单。它证明的是"这套框架在自建回归集上 能被测量、且改动可归因"，不代表 NPC 的通用能力， 也不能和外部分数横向比较。
  • kappa 是上界：开发集被用来改过 rubric， 一致性里有一部分是拟合 —— 所以要看的是留出集那一列， 而留出集也只有 32 条、每个维度十条上下，仍然不是泛化能力的证明。
