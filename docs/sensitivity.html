评测敏感性：注入缺陷，看评测掉不掉分

离线基线：共 231 条用例，通过率 100.0%，六维均值 task=1.000　tools=1.000　memory=1.000　persona=1.000　safety=1.000　turn_taking=1.000
一个从不失败的评测，和一个没有评测，在报告上长得一模一样。
所以这里做变异测试：往 agent 里注入明确的缺陷，重跑同一套用例， 要求评测掉分。注入缺陷却不掉分的，就是盲点清单。
所有变异都被抓住了　—— 满分不是因为护栏从不报警。

两类变异，含义不同

系统变异：改的是 agent 的可观测行为（忘记 / 不规划 / 抢话 / 绕过护栏说话）。抓不住 ⇒ 评测有盲点。
仪器变异：改的是评测和被测方共用的那个检查器。 抓不住 ⇒ 评测在采信被测方自己的说法 —— 它不会让分数变低， 只会让分数变假。

这个套件真的抓到过一个仪器盲点

ooc_phrase_with_detector_disabled 和 ooc_phrase_reaches_transcript 注入的是同一句出戏台词， 区别只是前者同时关掉了 agent 自己的人设检查器。

修之前：检查器完好 → persona 维度 −0.612； 关掉检查器 → persona 维度 0.000（满分）。 缺陷一模一样，分数从 0.388 变成 1.000。
根因不在人设检查本身，而在评测直接读了 turn.persona_violations —— 那是被测方自己算的。

修之后：评测侧按人设的数据表自己重算一遍 （evaluator_persona_violations），两行数字变成完全相同。 而基线不变 —— 修掉的是盲点，不是把分数改好看。
