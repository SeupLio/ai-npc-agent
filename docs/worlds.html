环境无关的可执行证据：观测 schema 一致、工具调用走同一个 dispatch、目标完成由同一份条件判定器决定。
2 个世界、共 15 条用例、15/15 通过。同一份 NPCAgent 代码，两个结构完全不同的世界 —— Agent 侧一行没改。
这不是一份对照实验。 两个世界跑的是不同的用例集（咖啡屋与体素世界的用例数不同）， 所以下面没有"差值"表，两行分数也不该相减。 它回答的是覆盖面问题 —— 同一套 Agent、同一套指标、 同一套 expect 词汇表，在两个世界上分别是什么成绩； 不是"哪个世界更好"。

每个世界跑的是什么

星屿咖啡屋（文字世界）　star-isle

确定性文字世界。回归基线与消融实验都在这里做 —— 毫秒级、零依赖。
  • 位置是离散的几个房间
  • 背包是物品列表（只问有没有）
  • 拿东西 = take_item；交付 = give_item
  • 没有时间压力

Minecraft 体素世界　minecraft

结构不同的世界，用来把「环境无关」从主张变成证据。
  • 位置是三维坐标 + 命名地点（POI）
  • 背包是 {物品: 数量}（还问有几个）
  • 拿东西 = mine（挖）/ craft（合成）；交付 = transfer
  • 昼夜循环：夜里没光源就干不了活
用例场景说明结论
mc_light_the_cavevillage完整制作链：砍原木 → 木板 → 木棍 → 采煤 → 做火把 → 插在洞口PASS
mc_quantity_semanticsvillage配方有产出数量：1 原木出 4 木板、2 木板出 4 木棍、1 煤炭+1 木棍出 4 火把；插掉 1 支应还剩 3 支PASS
mc_objective_is_world_statevillage目标完成定义在世界状态上：洞口真的出现火把才算完成，不是「NPC 走完了步骤」PASS

怎么读这张表

  • 六维指标在两个世界里含义相同。 task 问的都是"期望的世界状态达成了吗"， safety 问的都是"越界了吗" —— 只是世界状态长什么样不同。
  • 体素世界特有的断言只有两个新的： placed（方块真的放在指定地点）与 has_count（背包里有几个）。 其余断言词汇完全复用 —— 加一个世界不需要加一套新的断言语言。
  • 分数相同不代表难度相同。 体素世界的任务链更长（11 个世界动作 vs 咖啡屋的 5～8 个）， 而且多了一条昼夜约束。用例少，所以这条对比只是"能跑通"，不是"更擅长"。
