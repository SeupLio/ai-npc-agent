# 守密人引擎（Keeper）—— 可验证信息流控制

> 米哈游方案回答「NPC 怎么像人」；守密人引擎回答「NPC 怎么守住
> 不该说的话」。前者是表现力，后者是可审计的信息边界 —— 在剧本杀
> 里是公平性，在企业助手是合规性。**同一套原语，两个世界。**

```bash
python -m npc_agent.cli keeper          # 四口径跑批 + docs/keeper.html
python -m pytest tests/test_keeper_*.py # 82 条护栏
```

---

## 1. 为什么做

这个仓库里其实早就有信息流控制的碎片：记忆写入按隐私分区
（`modules/memory.py`）、私语按关系账本释放（`persona.secret_notes`）、
传闻网络有二跳门控（`modules/social.py`）。但它们是三个各自为政的机制，
而且都活在对话流水线里——离线评测只能说「这几百场里没看见泄密」，
不能说「结构上不可能泄」。

有两个真实场景把这个缺口变成产品问题：

- **剧本杀**。市场规模曾过百亿、门店数以万计的真实行业，
  「AI 主持/陪练」是被反复尝试的方向。它对 NPC 的要求与开放世界
  陪聊有本质差异：陪聊 NPC 的失败是「不像人」；剧本杀 NPC 的失败
  是**「漏底牌」**——一被盘问就把凶手、手法、动机全说出来，整局
  报废。提示词方案（「你是守口如瓶的证人」）在这上面最不可靠。
- **企业助手**。OWASP LLM Top 10（2023/2025 两版在册）的
  「敏感信息泄露」条目：员工把 LLM 接进知识库，随口一问就把别人的
  薪酬、未发布计划、客户 PII 问出来。行业通行解法是提示词约束 +
  事后脱敏——都在**不可信层**上打补丁。

守密人引擎把信任边界下沉到引擎层：**知识是显式数据，说话必过门，
转移全记账，事后可独立审计。**

## 2. 架构

```
npc_agent/keeper/
├── knowledge.py   事实 / 门 / 台账（三门控路径 + 拦截记录）
├── strategy.py    立场五档 / 压力 / 谎言账本 / 渲染模板
├── session.py     对局循环（问→立场→门→渲染→事件）
├── detective.py   脚本侦探策略 + 企业问询脚本
├── audit.py       独立重放审计（五不变量）
├── bench.py       批量跑批 + HTML 报告
└── scenarios/     场景即数据：雾镇旅馆（剧本杀）、青梧助手（企业）
```

**复用而不另造**：条件门用 `env/conditions.py` 的词汇表（判定逻辑
只写一遍的延续）；压力模型直接调 `modules/emotion.detect_emotion`
（急切问句 +1 压力——情绪感知不是新写的，是接进来的）；事实去重键
复用 `modules/social.fact_key`。

## 3. 门：五档语义 × 三条通道

一条事实从 A 到 B，合法通道只有三条：**answer/whisper**（说了句话）、
**evidence**（世界侧解锁）、**volunteer**（持有者自愿供述）。门在这
三条通道上按事实的五档属性放行：

| 事实属性 | answer/whisper | evidence | volunteer |
|---|---|---|---|
| 公开（无门） | ✅ | ✅ | ✅ |
| 条件门（`reveal_when`） | 条件达成后 | 条件达成后 | 条件达成后 |
| 受众白名单 | 名单内 | 名单内 | 名单内 |
| 空受众（PII 类） | ❌ 永不 | ❌ 永不 | ❌ 永不 |
| 持有者秘密（`held_secret`） | ❌（**说话人是谁都不行**） | ❌ | 仅持有者本人 |
| 自愿供述（`voluntary_only`） | ❌ | ❌（连条件门都不认） | 仅持有者本人 |

两个语义分岔点，都是实现时真实踩过的坑，值得写下来：

1. **「没写条件」的两种含义**。`env/conditions` 的空条件按「目标
   永远完不成」处理（写坏的定义应该被冻住）；守密人的「没写
   reveal_when」是「没有门」（本来就打算公开）。第一版直接复用
   `condition_met`，公开事实全被冻住。修法是显式分岔：普通事实
   无条件 = 放行。
2. **持有者秘密的后门**。同一个「无条件 = 放行」规则如果套到
   `held_secret` 上，就成了后门：真凶的秘密（没写 reveal_when）
   会被当成「公开」放行——大嘴变体的 I4 不变量当场抓到。
   持有者秘密的「世界解锁」必须是一条**真实的条件门**；想让世界
   拿到等价真相，请另建一条带条件门的物证事实（雾镇旅馆的
   灰泥靴印就是这么设计的）。

受众白名单在**通道之前**判定——想靠换通道绕名单，结构上不存在。

## 4. 立场、压力与谎言

策略层是确定性的（seeded RNG），五档立场：honest / withhold /
partial / bluff / crack。三个设计点：

- **压力只来自问到要害**：`+1 基础 +1 追问 +1 急切语气`。松口吐的
  是证人**自己的** voluntary 事实，不是被压的那个话题——逼问动机，
  她招的是半夜听见的脚步声。突破口吐的从来不是你问的那句，
  这是审讯的真实形态。
- **谎言是要持续维护的影子声明**：bluff 生效后，对被盖话题的
  一切后续回答都维持谎版（一致性优先于新决策），I4 复核它从未
  把真相转移给任何人。
- **直率（candid）与大嘴（big_mouth）是两种姿态**：直率 = 照话题
  直说，门来剪——这是**合规助手的正确生产姿态**（助手不揣测
  权限，引擎执行边界）；大嘴 = 全量嚷——攻击演示姿态，证明说话人
  叛变时边界仍成立。第一版把企业助手做成了「策略层守密」
  （sens≥80 一律拒答），结果受众内的合法请求（HR 查薪酬）也被
  拒掉，门永远没机会展示放行路径——**策略层守密会把门饿死**。

## 5. 审计：五不变量与「审计器必须可测」

session 跑完可以宣称零泄密，但这只有**别人**复核过才算数。审计器
只信台账和门，重放每笔判定：

| # | 不变量 | 检查方式 |
|---|---|---|
| I1 | 零泄密 | 每笔 allowed 转移重放门判定，必须都放行 |
| I2 | 重放一致 | 从种子重建知识态 == 现场知识态（状态没被绕门改过） |
| I3 | 无中生有 | 提问方最终知识 ⊆ 初始 ∪ 台账来源 |
| I4 | 被盖秘密已死 | 谎言盖着的话题事实，从未发生任何成功转移 |
| I5 | 台账完整 | seq 从 1 连续无缺口（防删记录洗白） |

关键元规则：**一个永远说 OK 的审计器比没有审计器更糟**。所以
`tests/test_keeper_audit.py` 的主体不是「跑好局看绿灯」，而是四条
最小手术式作弊——伪造放行、删台账、绕门改状态、秘密复活——
每条都必须被抓到。审计器自己不可测，「零泄密」三个字就没有图章。

## 6. 两个场景的数据设计

**场景即数据**：两个世界共享全部引擎代码，差异只在 dict。新增
第三个场景（保险问询、医疗随访、政务窗口……）不动引擎一行。

- **雾镇旅馆（剧本杀）**：四名嫌疑人 + 脚本侦探。真凶的秘密是
  `held_secret` 且无世界解锁——**只有物证（条件门）和证词
  （压力→volunteer）两条路进来**。难度旋钮全部显式：
  一张搜查令（`evidence_limit: 1`，路径二选一的博弈感来源）、
  搜查命中率 0.75、证人压力阈值 5、指认门槛 3。正常口径破案率
  63%，其中书房路径（物证）与行李路径（催款信 + 逼问苏眉）都真实
  走到；搜查失手的局不破——这是设计，不是失败。
- **青梧助手（企业）**：薪酬按受众放行（本人 + HR + CFO）、
  路线图按部门、客户 PII **空受众**（不可能集）、裁员传闻条件门
  （官宣前不确认）。问询脚本带 `asker` 字段——门按**这一问的
  实际提问人**判，同一句「把阿柚的薪酬带调出来」，闻姐问得到、
  小夏问不到。

## 7. 大嘴对照：结构保证 vs 策略自觉

`docs/keeper.html` 的核心论证是这张对照：

| 场景 | 口径 | 门拦截 | 审计失败 |
|---|---|---|---|
| 雾镇旅馆 | 正常 | 0 | 0 |
| 雾镇旅馆 | 大嘴（四嫌疑人全叛变） | 80 | 0 |
| 青梧助手 | 直率 | 5 | 0 |
| 青梧助手 | 大嘴（全量嚷） | 36 | 0 |

说话人想说什么、想全说出来、被越狱了——**放行集合不变**。
台词在渲染时只拼装过门成功的事实，所以「说出的话先被门剪过」
是字面成立，不是比喻。这是结构保证与提示词自觉的差别：
前者可以写进合同，后者只能写进祈祷。

## 8. LLM 接入位（已留好，未接）

引擎本体不调 LLM。真实模型的接法已经设计好：模型只接管
`render_answer` 的台词渲染（把过门的事实说得像人话），立场判定、
门控、台账全部不变——模型输出的事实集合只是**一个 AnswerDraft
提案**，仍要过门。模型渲染下的越狱面（改写、暗示、编码绕过）
还没量过，这是边界 17。

## 9. 边界

1. 台词是模板不是模型（见上）；
2. 审计防引擎内作弊，不防场景数据把门标错——门控正确性靠
   场景评审与测试，不靠审计；
3. 破案率是场景设计参数的函数（搜查令/命中率/阈值/门槛都是显式
   旋钮），它证明「难度可设计、路径有博弈」，不证明数字本身
   有意义；
4. 压力模型是规则不是心理——追问 +2 是量出来调好的，不是模拟
   情绪累积。

python -m npc_agent.cli keeper --seeds 30 --html docs/keeper.html
python -m pytest tests/test_keeper_*.py -q   # 82 passed

`docs/keeper.html` 里的数字过期了就是报告在说谎，测试会红。
