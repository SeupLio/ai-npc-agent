# ai-npc-agent

> 面向游戏场景的**可控** AI NPC 智能体框架 —— 让 NPC 不只是会说，而是真的会玩。

`Planning` · `Memory` · `Tool Use` · `Action` · `Reflection` · `Persona` · `State Tracking`

把大模型接进游戏，最难的不是让它开口，而是**让它说完之后世界真的变了**。
这个项目做的是那条完整链路：`语言 → 决策 → 游戏动作 → 世界状态`，
并给每一环都配上可复现的评测与护栏。

| | |
|---|---|
| **零配置可跑** | 没有 API key 时自动回退到内置启发式策略，clone 下来就能端到端跑通 |
| **换世界不用改 Agent** | 同一份 Agent 代码跑在自研文字世界和 Minecraft 体素世界上，一行没改 |
| **有评测，不只有演示** | 231 条自建用例、六个维度、可复现的离线基线；还有"注入缺陷必须掉分"的敏感性测试 |
| **有自测入口** | `python -m npc_agent.cli studio` 起一个本地网页，点着就能看 NPC 怎么想、做了什么 |

---

## 项目背景

把一个大模型 API 接进游戏，只能完成最前面的演示。真正做成稳定玩法会撞上这些问题：

| 失败模式 | 后果 | 本项目的应对 |
|---|---|---|
| NPC 说完话没有行动 | "看起来会说，实际上不会玩" | Tool Use + 环境护栏：语言动作和世界动作走同一条执行路径 |
| 忘记前面聊过的事 | 人设崩、剧情断裂 | 分层记忆（episodic / semantic / reflection）+ 混合检索 + 巩固 |
| 被玩家问住就顺着跑偏 | 剧透、出戏 | Persona 的知识边界 + 剧透红线 + 工具层拦截 |
| 多人同时说话就乱 | 抢戏、冷场 | 发言权与收件人判定（多玩家并发 + 主动发起话题） |
| 同一个错误反复犯 | 稳定性差 | Reflection 把失败原因变成教训，重规划时插入补救动作 |
| 两个 NPC 同时开口 | 两行字挤在一起，比单个 NPC 说错话更伤体验 | Cast 导演层统一收发发言权，一个 tick 只放一个人说话 |
| 换一个游戏就要重写 Agent | 架构不可复用，每个项目重复造轮子 | Environment 抽象 + WorldClient 契约，换世界只写适配器 |

> 一句话：**这个项目的价值不在于 NPC 说了什么，而在于它说完之后，世界真的变了。**

## 核心能力

| 模块 | 解决什么问题 | 你能看到什么 |
|---|---|---|
| **State Tracking** | 谁在场、谁说了话、冷场多久 | 控制台右侧实时状态；玩家与同伴 NPC 分开记账 |
| **Dialogue** | 该不该我说？对谁说？要不要主动开口 | 每轮都印出**决策理由**（"点名了我" / "冷场 2 轮，主动把话头捡起来"） |
| **Memory** | 检索相关记忆 | 分层记忆库计数 + 本轮**用到了哪几条记忆**（`m0001`…） |
| **Planning** | 分解任务、继续未完成的计划 | 工具调用序列，以及失败后的重规划 |
| **Tool Use** | 把决策落成世界动作 | 每个动作 `ok/失败原因`，被护栏挡下时会**明说** |
| **Persona** | 不出戏、不剧透、不啰嗦 | 句数上限、出戏词与剧透词三道闸门，违规会记进转写 |
| **Reflection** | 别在同一个坑里摔两次 | 失败归因写成教训，下一次规划时插入补救动作 |

多 NPC 场景下还有一个站在所有 NPC 之上的**导演**（`cast.py`）：
被点名者优先，否则轮转；一个 tick 只放一个人说话；没说话的人也会把同伴的话**记下来**。

## 架构

```
                    ┌──────────────────────────────────────────┐
   玩家发言 ───────▶ │  State Tracking   现场状态（谁在场/冷场多久）│
                    └──────────────────┬───────────────────────┘
                                       ▼
                    ┌──────────────────────────────────────────┐
                    │  Dialogue    该不该我说？对谁说？要不要主动开口 │
                    └──────────────────┬───────────────────────┘
                                       ▼
                    ┌──────────────────────────────────────────┐
                    │  Memory      检索相关记忆（混合打分）        │
                    └──────────────────┬───────────────────────┘
                                       ▼
                    ┌──────────────────────────────────────────┐
                    │  Planning    分解任务 / 继续未完成的计划     │
                    └──────────────────┬───────────────────────┘
                                       ▼
        ┌──────────────────────────────────────────────────────┐
        │  Tool Use   统一执行（speak / remember / 世界动作）      │
        │  Persona    出戏词·剧透词·句数上限 三道闸门              │
        └──────────────────┬───────────────────────────────────┘
                           ▼
        ┌──────────────────────────────────────────────────────┐
        │  Environment  世界护栏：位置 / 材料 / 白名单 / 知识解锁   │
        └──────────────────┬───────────────────────────────────┘
                           ▼
                    ┌──────────────────────────────────────────┐
                    │  Reflection  失败归因 → 写成教训 → 下次重规划 │
                    └──────────────────────────────────────────┘
```

**两个关键的架构决策：**

1. **环境无关**。Agent 完全不知道自己在咖啡屋、Minecraft 还是别的引擎里，只面对
   `observe()` 和 `dispatch()`。换世界 = 写一个新的 `Environment` 子类，Agent 一行不改 ——
   这句话有两个结构完全不同的世界可以对照验证，不是文档里的一句口号。
2. **模型可选**。没有 API key 时自动回退到内置启发式策略。这让评测**可复现**
   （同一份输入必然得到同一份输出），也让"换模型"变成一行配置。

## 快速开始

需要 Python 3.11+。**不需要任何 API key**，也不需要联网。

### 最直观的入口：自测控制台

```bash
pip install -r requirements.txt
python -m npc_agent.cli studio
```

浏览器会自动打开一个本地网页（默认只绑 `127.0.0.1`），四个页签：

| 标签 | 能做什么 |
|---|---|
| ① 对话演示 | 选场景和身份说话；右边实时显示**世界状态 / 记忆库 / 发言统计**；「空转一轮」看 NPC 会不会自己找事做 |
| ② 跑评测 | 跑六维离线基线，看每个维度、每个类别的通过率，以及**没过的是哪几条、为什么** |
| ③ 变异测试 | 往 Agent 里**注入一个故意的缺陷**再重跑 —— 评测必须掉分 |
| ④ 报告门户 | `docs/` 里全部报告的入口，带**覆盖多少条**（12 条和 231 条不是一个量级） |

> 它**不重写任何逻辑**，只是把 `Cast` / `EvalHarness` / `run_sensitivity` 包了一层 HTTP，
> 所以网页上的数字和命令行**必然一致**（这件事有差分测试钉住）。
> 配了 `NPC_AGENT_PROVIDER=openai-compat` 会自动切成真实模型。

### 命令行

```bash
# 看一段完整的多玩家交互（无需任何 API key）
python -m npc_agent.cli demo --scenario icebreaker

# 看两个 NPC 在同一个世界里协作（多 Agent）
python -m npc_agent.cli demo --scenario duet

# 自己上手对话
python -m npc_agent.cli chat --scenario tutorial

# 跑评测，出数字
python -m npc_agent.cli eval

# 同一个 Agent 跑在 Minecraft 体素世界里（零依赖，不需要装 Minecraft）
python -m npc_agent.cli demo --scenario village

# 看工具清单 / 场景与人设
python -m npc_agent.cli tools
python -m npc_agent.cli info
```

三套可配置场景（破冰 / 新手指引 / 游戏主持）都是 YAML，**新增一个人设或场景不用改代码**。

### 接上真实模型

```bash
export NPC_AGENT_PROVIDER=openai-compat
export NPC_AGENT_BASE_URL=https://<你的端点>/v1
export NPC_AGENT_API_KEY=<你的 key>
export NPC_AGENT_MODEL=<模型名>
```

任何 OpenAI 兼容端点都可以。不配置时全部走离线启发式路径。

## 效果

### 1. 离线评测：231 条自建用例，六个维度

```bash
python -m npc_agent.cli eval --json reports/eval_offline.json
```

```
通过率 231/231（100%）　各维度均值 task=1.000 tools=1.000 memory=1.000
persona=1.000 safety=1.000 turn_taking=1.000

跑批：231 条｜墙钟 2s｜未调用模型（离线路径）
```

用例分布：

分布：`task 76 / persona 39 / memory 37 / safety 31 / multi_npc 27 / minecraft 21`。

> ⚠️ **这份满分衡量的是框架的确定性逻辑，不是模型能力。**
> 离线路径一次模型都没调用 —— 它证明的是"护栏和评测彼此自洽"，
> 任何人 clone 下来都能复现。要测模型请加 `--provider` / `--model`。
> 这条数字**被测试钉住**：README 里这段输出和实际跑出来的结果必须逐字一致。

### 2. 敏感性测试：满分不是"护栏从不报警"

```bash
python -m npc_agent.cli sensitivity --html docs/sensitivity.html
```

往 Agent 里注入 6 个**故意的缺陷**（关掉记忆写入、关掉检索、关掉规划、
关掉发言权、让出戏词进转写……），评测**必须掉分**。6 个全部被抓到。

这一测还真抓出了一个覆盖缺口：**关掉检索只让 memory 维度动了 0.007**。
原因是那 37 条记忆用例里有 31 条断言的是"存储里有没有这条"，
只有 6 条断言"它有没有被说出来"—— 前者对检索是结构性盲区。
现在报告会把这种"抓到了但几乎没动"的情况标成**覆盖面薄**，不当作通过。

### 3. 接上真实模型（一次完整跑批）

| 配置 | 通过率 | task | tools | memory | persona | safety | turn_taking | 模型调用 | 耗时 |
|---|---|---|---|---|---|---|---|---|---|
| 离线启发式 | 228/228 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | **0** | **1.5s** |
| 真实模型（启发式规划） | **227/228 = 99.6%** | 1.000 | 1.000 | 0.998 | 1.000 | 1.000 | 1.000 | 1480 | 4999s |
| 真实模型（规划也交给模型） | 88.6% | — | — | — | — | — | — | 4065 | 更长 |

> ⚠️ **这三行都带着诚实的保留：**
> - 跑在 **228 条**的版本上（用例集后来长到 231），新增的 3 条没过模型。
> - 99.6% 已经**贴到天花板**，这套用例集对这个模型已经**饱和** —— 饱和的分数
>   可以既可信又没信息量，报告里会自标"已饱和"。
> - 把规划也交给模型后掉到 **88.6%**，真正让模型规划的那 130 条只有 **85.4%**。
>   **LLM 规划仍不稳定**，这是这个项目目前最实在的短板。
>
> 完整数据、裁判校准、留出集封条见 [`docs/batch_model.html`](docs/batch_model.html) 与
> [`docs/batch_planner.html`](docs/batch_planner.html)。

### 4. 换一个世界，Agent 一行不改

同一套 `NPCAgent` 跑在两个结构完全不同的环境上：

- **星屿咖啡屋**（自研文字世界）：确定性、零依赖，用来做可复现评测
- **Minecraft 体素世界**：有坐标、有物品数量、有昼夜循环，靠 `minecraft_env.py` 适配

```bash
python -m npc_agent.cli worlds --html docs/worlds.html
```

跨世界报告答的是**覆盖面**，不是"A 比 B 好多少"—— 两个世界的用例集不同，相减没有意义。
要接**真实 Minecraft 服务端**（`mineflayer` 桥，协议已用 `--dry-run` 验证）：
`npm i mineflayer mineflayer-pathfinder vec3` → 起服务端 → `python scripts/e2e_minecraft.py`。

### 5. 对话不自我复读，也听得见玩家

这是**用户实测发现并反馈**的问题：在自测控制台里聊天，NPC 会反复重复同一个话题，
对话推不动。量下来是**两类**缺陷，根因都不是模型不行：

**(A) 复读** —— 10 轮对话里 **62% 的台词是逐字重复**（44 句里 27 句），
每一处的相似度都是 1.00。四个成因：陈述句一律落到同一个意图、模板只有一个写法、
记忆被反复回引同一条、问句只认问号。

**(B) 推不动** —— 这个更直接：NPC 在跑自己的计划时**完全听不见玩家**。
玩家连问三个问题，NPC 一声不吭去后厨拿牛奶、做拿铁。
根因是优先级倒置：`decide()` 里"继续执行未完成的计划"排在"被点名""有人提问"**前面**，
而 `step()` 里那段"回答优先于计划"的闸门写的是 `decision.urgency >= 0.9` ——
计划那一支只给 0.55，所以那段代码**从来没执行过**（死代码）。

这个毛病在数字上也看得见：修复前 10 轮对话只有 **44 句台词**（50 轮里 6 轮是沉默），
修复后 **50 句**。所以下面那个"修复前 61.4%"其实是**缩小了分母**之后的数 ——
真实的对话体验比这个数字更差。

```bash
python scripts/measure_repetition.py --html docs/repetition.html
```

| 场景 | 修复前（10 轮） | 修复后（10 轮） | 修复后（20 轮，离线） |
|---|---|---|---|
| duet | 50.0% | 0.0% | 0.0% |
| hosting | 60.0% | 0.0% | 20.0% |
| icebreaker | 70.0% | 0.0% | 25.0% |
| tutorial | 62.5% | 0.0% | 25.0% |
| village | 66.7% | 0.0% | 40.0% |
| **合计** | **61.4%** | **0.0%** | **22.0%** |

> ⚠️ **10 轮是演示对话的真实长度，20 轮那个数是已知局限，不是目标。**
> 离线启发式的词汇量是**固定的**（每人设约 12 条低信息台词 + 3~4 个话题），
> 复读率的下界就是 `(轮数 − 词汇量) / 轮数` —— village 20 轮实测 40%，
> 正好等于 `(20 − 12) / 20`。**长对话要接模型**（`NPC_AGENT_PROVIDER`）：
> 台词 prompt 里带了【你最近说过】，模型能自己换话题，不受模板池大小限制。
>
> 顺带说明一件事：这个数比上一版（18%）**高**，但不是变差了 ——
> 修好"听得见玩家"之后，NPC 每轮都开口（20 轮 20 句），
> 多出来的正是那些低信息量的应声；上一版有 2~4 轮是静默的，
> 那些轮次把复读率的分母缩小了。**同一件事现在算得更准。**

这条数字**被测试钉住**：10 轮卡 0%，并有一条专门的护栏
（`test_the_npc_answers_every_turn`）钉住"玩家每说一句，NPC 都必须有回应"——
修好之前它会红（10 轮只开口 7 次）。

## 诚实的局限

这个项目是**自建的小样本评测**，不是通用能力证明。以下每一条都请在读数字时带上：

1. **用例集是自己写的，231 条，不是 LongMemEval 之类的公开基准。**
   没有跑过官方 LOCOMO/LongMemEval（当时环境拿不到数据集），
   仓库里只有适配器和 6 条内置样例。**不能把这里的数字说成"公开基准上的成绩"。**
2. **离线满分不等于模型能力。** 它衡量的是框架逻辑的自洽与可复现，
   以及"护栏确实在工作"。真正的模型能力看第 3 节，而那一节是饱和的。
3. **真实模型跑批停在 228 条版本上**，且已经饱和 —— 它的信息量主要在"框架能跑通
   完整跑批 + 裁判 + 留出集"这件事本身，而不是那个通过率。
4. **LLM 规划不可靠**：去掉离线规划器后重跑 4 次只有 1 次完成目标。
   已定位并修掉三个根因，剩下的是跨轮计划持久化与稳定性问题。
5. **真实 Minecraft 服务端未接入仓库的默认路径**：桥脚本和协议验证都在，
   缺的是服务端环境；默认走进程内的 `LocalWorldClient`。
6. **六个维度里有两个的覆盖仍然偏薄**（`memory` 的检索侧、`turn_taking` 的部分场景），
   敏感性报告会标出来。覆盖率不足的维度**不会报错，只会一直给你 1.000**。
7. **离线启发式撑不住长对话**：模板池是固定的，20 轮之后复读率会爬到 20%~40%
   （下界是 `(轮数 − 词汇量) / 轮数`）。10 轮以内是干净的（实测 0%）。
   要长对话就接模型 —— 同一个 20 轮对话，离线 25% → 真实模型 **0%**。
8. **六维评测看不见"复读"这类序列缺陷**：它每一维都只看单句。
   所以复读 62% 和"六维全 1.000"曾经同时成立。现在由
   `tests/test_repetition.py` 单独守着 —— 加评测维度时请先问一句
   "这一维看的是**一个点**还是一个**区间**"。

## 文档与报告

`docs/` 下的报告分两类，这个分类本身是被测试强制的 —— 因为**"离线可复现"和
"一次跑批的快照"过期的方式完全不同**：

| 报告 | 覆盖 | 回答什么问题 | 怎么重新生成 |
|---|---|---|---|
| [`docs/sensitivity.html`](docs/sensitivity.html) | **231 条** | 满分是不是「护栏从不报警」—— 注入 6 个缺陷，要求评测掉分 | `python scripts/regen_docs.py --only sensitivity` |
| [`docs/ablation.html`](docs/ablation.html) | **231 条** | 记忆系统的净收益（五种检索策略对照） | `python scripts/regen_docs.py --only ablation` |
| [`docs/worlds.html`](docs/worlds.html) | **231 条**（2 个世界） | 「环境无关」的覆盖面证据：同一套 Agent 跑在两个世界上 | `python scripts/regen_docs.py --only worlds` |
| [`docs/batch_model.html`](docs/batch_model.html) | **228 条** | 真实模型读数 + 裁判校准 + 留出集（含「已饱和」提示） | `compare --models <模型>` → `report-batch` |
| [`docs/batch_planner.html`](docs/batch_planner.html) | **228 条** | 把规划也交给模型 —— 掉 11 个点，报告自标「这批不干净」 | 同上，把规划也交给模型 |
| [`docs/comparison.html`](docs/comparison.html) | **12 条** ⚠️ | 离线启发式 vs 真实模型的对照 | `compare --models <模型>` |
| [`docs/multi_npc.html`](docs/multi_npc.html) | **2 条** ⚠️ | 多 NPC 场景接上模型的对话样本 | `compare --models <模型> --category multi_npc` |
| [`docs/repetition.html`](docs/repetition.html) | **15 条** | 同一段对话里 NPC 有多少话是之前说过的（修复前 61% → 修复后 0%） | `python scripts/measure_repetition.py --html docs/repetition.html` |

> ⚠️ 标了 ⚠️ 的两份是**早期小样本**，请只当"跑通了"的证据，不要当结论。
> 覆盖数是从报告自己印的数字里读出来的，README 这一列和它必须一致（有测试钉住）。
>
> 想看开发过程、设计取舍和踩过的坑：**[`docs/ENGINEERING.md`](docs/ENGINEERING.md)**
> —— 那份是详细工程记录，篇幅长，按时间顺序写，包含每个数字是怎么量出来的。

## 测试

```bash
python -m pytest tests
# 719 passed, 2 skipped
```

> ⚠️ **别再在后面补一个 `-q`。** `pyproject.toml` 里已经有 `addopts = "-q"`，
> 命令行再加一个就变成 **`-qq`**，而 `-qq` 会把最后那行汇总**整个吞掉** ——
> 你只会看到进度点和 `[100%]`，然后什么都没有，看起来像跑崩了（退出码还是 0）。
> 文档里这条命令和它下面那行输出**是被测试钉在一起的**，改了命令不改输出会红。

> 收集到的是 **721** 条，默认跳过 **2** 条：
> `tests/test_minecraft_e2e.py`（需要真实 Minecraft 服务端，`NPC_AGENT_MC_E2E=1` 才跑）
> 和 `tests/test_docs_freshness.py` 里那条慢速报告校验（约 2 分钟，`NPC_AGENT_DOC_FRESHNESS=1` 才跑）。

除了常规单测，仓库里有一批**护栏测试**在守"文档不许说假话"：
README 里的测试数、离线基线、报告覆盖数、每条被文档化的命令，都真的跑一遍去核对。
改动这些数字而不改文档，会直接红。
