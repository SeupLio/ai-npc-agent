# ai-npc-agent

> 面向游戏场景的**可控** AI NPC 框架 —— 让 NPC 不只是会说，而是真的会玩。

`Planning` · `Memory` · `Tool Use` · `Action` · `Reflection` · `Persona` · `State Tracking` · `Multi-NPC Dialogue`

| | |
|---|---|
| **零配置可跑** | 没有 API key 时自动回退到内置启发式策略，clone 下来就能端到端跑通 |
| **游戏引擎接得进** | `python -m npc_agent.cli serve` 起 HTTP API：会话/发言/事件流/存档，Unity/Godot/Web 直接调（[接入指南](docs/GAME_SERVER.md)，含三端最小样例） |
| **成本可算账** | 真实 token 计量 + p50/p95/p99 双口径延迟 + `cli cost` 成本画像：上线前回答"一万个玩家聊十轮要花多少" |
| **NPC 之间能对话** | 两个 NPC 会互相点名、转达、接话，而不是各说各的 |
| **听得懂语气** | 玩家喊「娜洛！！」NPC 会惊慌问怎么了；投诉先安抚、夸赞接得住（判据离线可复现，误伤有回归盯着） |
| **记忆有分寸** | 专属称呼只对约定的人生效——别人冒用会被当面拒绝并说出主人是谁（跨会话存档后仍然成立） |
| **NPC 会主动开小窗** | 关系到位的老客，NPC 冷场时会私下告诉他一件只有他知道的事（一次性，第三人听不见） |
| **记忆会代谢** | 每条记忆带来源、跳数、保真与确信；转述有损、确信反升；长期不用的会归档成"记不清"，秘密不进传闻 |
| **守得住秘密** | 守密人引擎：NPC 说不说不靠提示词求它，信息流走引擎层门控 + 台账，零泄密可审计——同一套原语跑剧本杀对抗守密和企业助手合规边界（说话人全面叛变也泄不出去，见 [docs/keeper.html](docs/keeper.html)） |
| **有评测，不只有演示** | 235 条回归用例 + 18 条多 NPC 对话基准 + 24 条世界能力基准，可复现的离线读数，外加"注入缺陷必须掉分"的敏感性检验 |
| **有自测入口** | `python -m npc_agent.cli studio` 起一个本地网页，点着就能看 NPC 怎么想、做了什么 |

**这份 README 怎么读**：先说清楚要解决什么问题（一、二），再讲能做什么、怎么跑（三、四），
然后是效果与边界（五、六）。想看工程细节请看 [`docs/TECHNICAL.md`](docs/TECHNICAL.md)，
那里才有模块划分、设计取舍和踩坑记录。

## 一、为什么做这个

把一个大模型 API 接进游戏，只能完成最前面的演示。真正做成能上线的玩法，
会连续撞上七道坎 —— 这七条不是我编的，是米哈游公开的 AI 生态方案里
反复提到的那几件事，也是任何做"活世界"的团队都会撞上的：

| 痛点 | 玩家的体感 | 本项目的应对 |
|---|---|---|
| 说完话没有行动 | "看起来会说，实际上不会玩" | 语言动作和世界动作走同一条执行路径，每个动作都带回成功或失败 |
| 忘记前面聊过的事 | 人设崩、剧情断裂 | 分层记忆（短期对话 / 长期事实 / 反思教训）+ 混合检索 |
| 被问住就顺着跑偏 | 剧透、出戏 | 人设的知识边界 + 剧透红线，在工具层拦截而不是在提示词里"请求" |
| 多人同时说话就乱 | 抢戏、冷场 | 发言权由导演层统一收放，一个时刻只放一个人说话 |
| 同一个错误反复犯 | 稳定性差 | 失败归因写成教训，下一次规划时插入补救动作 |
| **两个 NPC 聊不起来** | **两个人各说各的，玩家插不上话** | **对话线程层：接话义务 + 话题账本 + 连聊上限** |
| 换一个游戏就要重写 | 架构不可复用 | 世界抽象成统一接口，换世界只写适配器，Agent 一行不改 |

后两条是这次重点补的。**"NPC 之间聊不起来"是最容易被演示掩盖的一类缺陷**：
单个 NPC 看起来都正常，六维评测也全绿，但把两个 NPC 放在同一个房间里，
你会发现它们从头到尾没有真正对话过。

## 二、这套东西的设计取向

三条，每条都对应一个具体的取舍：

1. **要的是可控，不是能力上限。** 什么时候**不说话**、什么话**不能说**、
   失败了怎么**归因** —— 这类"边界"在通用 Agent 框架里没有位置，
   而它们恰恰是 NPC 体验崩掉的地方。所以边界都放在工具层，能被测试钉住。
2. **演示能跑 ≠ 可评测。** 只接模型的话，同一份输入两次跑出不同结果，
   "改了代码有没有变好"就永远答不上来。所以默认路径是**确定性**的，
   模型是可插拔的上层。
3. **没有额度也要能复现。** 一个必须配 API key 才能验证的项目，
   别人（和三个月后的自己）都只能选择相信文档。所以离线路径是地基。

## 三、它能做什么

### 3.1 会说，也会做

NPC 说的话和它做的事走同一条路径：`speak`、`move_to`、`craft_item`、`give_item`
都是工具，都要过同一套护栏。所以"说了但没做"不会成为一类静默失败 ——
每个动作都带回结果，失败会进反思。

### 3.2 记得住

三层记忆：当前对话的上下文、值得长期记住的事实、以及从失败里总结的教训。
检索是混合打分（相关度 + 时间衰减 + 重要度），并且**回引过一次就不再回引** ——
否则 NPC 会每隔一轮把同一句旧话捡起来再说一遍。

### 3.3 NPC 之间能对话

这是这次改动最大的一块。三个机制缺一不可：

- **接话义务**：谁对谁说了话、下一轮该谁接，由导演统一记账，而不是靠 NPC 自觉；
- **话题账本**：同一件事说过没有。它比"逐字查重"高一层 ——
  换个说法说同一件事，逐字判据抓不到；
- **连聊上限**：NPC 之间最多来回三轮。玩家站在旁边看两个人聊十轮，
  不会觉得世界很活，只会觉得自己被晾着。

### 3.4 印象会在角色之间流动

玩家跟 A 说"我喜欢偏酸的"，过一会儿 B 会对另一个玩家说
"听 A 说，你喜欢偏酸的"。

传的不是聊天记录（所有人都听得见，传原话没有信息量），而是**判断** ——
"谁注意到了什么"。这也是"记忆共享"里最容易被忽略的一层。

### 3.5 不出戏、不剧透、不啰嗦

出戏词、剧透词、句数上限三道闸门都在工具层判定，违规会记进转写，
所以"NPC 有没有出戏"是可观测的，不是靠人眼看。

### 3.6 成本可控

单轮模型调用上限、会话 token 预算、循环检测（同一串动作重复就停）、
上下文裁剪（注入提示词的记忆只留最相关的一截）。
这四条对应的是很具体的一次事故：几十个 Agent 一起跑、没有上限、
连续跑了十几个小时。

### 3.7 换世界不用改 Agent

同一份 Agent 代码跑在两个结构完全不同的环境上：自研的文字咖啡屋，
和 Minecraft 体素世界（有坐标、有物品数量、有昼夜）。换世界只写一个适配器。

### 3.8 可评测

- **235 条回归用例**，六个维度（任务 / 工具 / 记忆 / 人设 / 安全 / 发言权）；
- **18 条多 NPC 对话基准**，六个维度（同伴接话 / 转达 / 有依据的回答 / 不复读 / 印象流动 / 发言权）；
- **24 条世界能力基准**，八个维度（世界观一致性 / 关系与称号 / 动机事件 / 注意力 / 记忆延续 / 记忆代谢 / 多 NPC 同场 / 分组与私聊）；
- **分组与私聊调度**：同一场戏里多个分组并行，每组每轮最多一个人开口；玩家可以对一个组说，也可以悄悄说给某一个人 —— 回复仍是私聊，其他角色听不见也记不住；
- 三套都配了**敏感性检验**：往框架里注入一个故意的缺陷，评测必须掉分。

### 3.9 世界有设定、有关系、有动机

这三件事是"活世界"里最像产品的部分，也是最容易被做成"配置里写着、玩家看不见"的部分：

- **设定说不错**：世界有一本设定书（店在哪、什么来历、露台朝哪），
  说错的话在工具层被拦下 —— 和出戏词、剧透同一个位置。
  同时设定书会进提示词，让模型**少犯错**，而不是只靠事后拦截。
- **认得出回头客**：好感从 50 起步，一次递饮品 +4；跨过阈值就升阶段
  （生客 → 面熟 → 常客 → 老友），NPC 的招呼语跟着变，
  并且会在某个时刻**当面把称号说出来**（"从今天起，你是这家店的熟面孔"）。
  只存进数据库的称号，玩家看不见。
- **有自己的动机**：多个 NPC 可以想要互相冲突的东西（一个想早点收摊，
  一个想再唱一首）。冲突按强度裁定，输的那一方**把让步说出口**；
  三个人抢同一件事也只产生一条事件，由让步方里最强的那个代表开口。
  这就是"涌现叙事"最小的闭环：动机不同 → 相互影响 → 世界变了。
- **欠你的回答会补**：问了但没被答上的问题会记一笔账，
  冷场时先补答，再去做自己的事 —— 而不是转头开始聊别的。

### 3.10 记忆会老化、会走样、会保密

存下来就永远原样，是最不像人的一种记忆。所以每条记忆都带**知识状态**：

- **来源**：亲历、转述（听谁说的、几跳）、推断、复盘。玩家问起时，
  NPC 能说「听阿柚说」，而不是把所有事都说得像自己亲眼见过。
- **转述有损，确信反升**：「阿澈喜欢偏酸的豆子，越酸越好」经阿柚传给小舟，
  细节「越酸越好」被剪掉，保真度降到 57%，但确信度升到 95% ——
  Studio 里把这种记录标成**「越传越确信」**。损失规则是可复现、可解释的，
  不是随机篡改。
- **遗忘不是删除**：长期不用、又不重要的记忆会归档。被问起时只说
  「……记不清了。只记得你提过这件事」，**不编造细节** —— 忘了就是忘了。
- **秘密有分区**：「别告诉别人」在写入时就被标成私密，不进传闻网络，
  另一个玩家问不到；当事人自己仍然问得出来。第二跳的 NPC 转述也不会绕过它。

### 3.11 守得住秘密：信息流控制从提示词层下沉到引擎层

「别告诉别人」式的记忆分区解决的是**NPC 自己的**秘密。但有一类问题
它不够用：**信息从 A 流到 B 这件事本身**需要被管控、被证明——

- 剧本杀 NPC 一被盘问就漏底牌，整局报废（现有 LLM 剧本杀产品的真实痛点）；
- 企业助手被员工随口一问，薪酬、路线图、客户 PII 就出来了
  （OWASP LLM Top 10 挂号的「敏感信息泄露」）。

主流做法是在提示词里求模型保密——那把信任边界放在了最不可信的一层。
守密人引擎（`npc_agent/keeper/`）把边界做成**结构**：

- **知识是显式数据**：谁知道什么，一条条事实挂在门上（公开/条件门/
  受众白名单/持有者秘密/自愿供述五档）；
- **说话必过门**：NPC 的台词在渲染时只拼装过门成功的事实——
  想说的话先被门剪过，字面成立；
- **全量台账**：包括被拦的尝试。「零泄密」要有「拦了多少」作证，
  不然只是零记录；
- **独立审计**：五条不变量（零泄密/重放一致/无中生有/被盖秘密已死/
  台账完整）由独立重放器复核，测试里有「篡改台账必被抓」用例——
  一个永远说 OK 的审计器比没有更糟。

同一套引擎跑两个真实场景：**雾镇旅馆**（剧本杀对抗守密：物证条件门、
证人压力突破口、谎版一致性、一张搜查令的路径博弈）和**青梧助手**
（企业合规：薪酬按受众放行、PII 空受众永不外发、裁员官宣前不确认）。
场景即数据——新增第三个场景不用动引擎一行代码。详细设计见
[`docs/KEEPER.md`](docs/KEEPER.md)。

## 四、快速开始

需要 Python 3.10+（CI 实跑 3.10/3.11/3.12 三版本矩阵）。**不需要任何 API key，也不需要联网。**

```bash
pip install -r requirements.txt
```

**最直观的入口：自测控制台**

```bash
python -m npc_agent.cli studio
```

浏览器会打开一个本地网页（只绑 `127.0.0.1`），四个页签：对话演示、跑评测、
变异测试、报告门户。它不重写任何逻辑，只是把框架包了一层 HTTP，
所以网页上的数字和命令行**必然一致**（有差分测试钉住）。

**接进你的游戏引擎**（Unity / Godot / Web）

```bash
python -m npc_agent.cli serve --port 8080
```

起一个 HTTP API：建会话 → 玩家发言 → 拿 NPC 台词与动作，带事件流和按玩家
存档。最小调用样例（三端）见 [`docs/GAME_SERVER.md`](docs/GAME_SERVER.md)。

**上线前算成本账**

```bash
python -m npc_agent.cli cost --scenario duet --repeats 5
```

跑一段可复现对话，给出双口径延迟分位、真实 token 用量、每 100 轮成本推算。
离线路径的读数是"框架地板价"（0 token）——接上真实模型再跑一次，
差值就是模型开销。

**命令行**

```bash
# 两个 NPC 在同一个世界里协作，会互相点名、接话
python -m npc_agent.cli demo --scenario duet

# 三个 NPC 同场：发言权要轮得过来，第三个人不能是背景板
python -m npc_agent.cli demo --scenario trio

# 四人两组：吧台与露台并行对话，同组轮流、不同组同时说话
python -m npc_agent.cli demo --scenario quartet

# 多玩家场景（店主同时面对几位客人）
python -m npc_agent.cli demo --scenario icebreaker

# 自己上手对话
python -m npc_agent.cli chat --scenario tutorial

# 跑回归评测，出数字
python -m npc_agent.cli eval

# 多 NPC 对话基准（六个维度 + 敏感性检验）
python -m npc_agent.eval.dialogue_bench
```

**关掉再进来，她还记得你**

```bash
python -m npc_agent.cli demo --scenario duet --save s.json   # 第一次进店
python -m npc_agent.cli demo --scenario duet --load s.json   # 第二次：她记得你的口味
```

`chat` 也支持同样两个开关。存的是记忆、关系、称号、编年史和时钟。

场景与人设都是 YAML，**新增一个角色或场景不用改代码**。

**接上真实模型**

```bash
export NPC_AGENT_PROVIDER=openai-compat
export NPC_AGENT_BASE_URL=https://<你的端点>/v1
export NPC_AGENT_API_KEY=<你的 key>
export NPC_AGENT_MODEL=<模型名>
```

任何 OpenAI 兼容端点都可以。不配置时全部走离线启发式路径。

## 五、现在能做到什么程度

> ⚠️ **先读这一句**：下面的离线读数衡量的是**框架逻辑与护栏**，
> 不是"这个 NPC 有多聪明"。离线路径一次模型都没调用。

### 5.1 回归基线：235 条，六个维度

```
通过率 235/235（100%）　各维度均值 task=1.000 tools=1.000 memory=1.000
persona=1.000 safety=1.000 turn_taking=1.000
```

分布：`task 80 / persona 39 / memory 37 / safety 31 / multi_npc 27 / minecraft 21`

这个满分的信息量**在顶部几乎没有** —— 它是回归基线，用来回答
"我这次改动有没有把框架弄坏"。三条独立的证据说明它不该被当成能力上限：
把记忆整个模块拿掉只掉 6 条；四种检索策略之间 Δ=0.000；把计划砍掉 10%
评测才开始掉分。这些阴性结果都留在报告里。

### 5.2 多 NPC 对话：18 条，六个维度

```
通过 18/18（100%）
  同伴接话 3/3　转达 3/3　有依据的回答 3/3
  不复读 3/3　印象流动 3/3　发言权 3/3
```

同样配了反向验证：关掉 NPC 对聊 → 14/18，掉的是"同伴接话"和"转达"；
关掉传闻 → 16/18，掉的是"印象流动"。**该掉的维度真的掉了**，
这才说明这份满分不是"判据从不报警"。
发言权这一维已经按 `(轮次, 分组)` 判撞车：两组在同一轮各说一句是并行，
不是抢话。

Studio 里可以直接选「公开 / 对某个组说 / 私聊某个人」。私聊的回复也保持
私聊，其他角色听不见、记不住，也不会从传闻里绕回来。

### 5.3 世界能力：24 条，八个维度

```
通过 24/24（100%）
  世界观一致性 3/3　关系与称号 3/3　动机事件 3/3　注意力 3/3
  记忆延续 3/3　记忆代谢 4/4　多 NPC 同场 2/2　分组与私聊 3/3
```

敏感性同样能证伪：掐掉设定书 → 22/24，掐掉关系账本 → 22/24，
掐掉动机裁定 → 20/24，掐掉注意力记账 → 23/24，读档时什么都不恢复 → 21/24，
掐掉记忆代谢 → 22/24，掐掉隐私分区 → 23/24，只调度前两个 NPC → 21/24，
掐掉频道隔离 → 22/24。

九个注入全部被抓到 —— 包括"第三个人全程不开口""秘密在第二跳被念出来"
和"两个组互相串台"这种**其它指标全绿**的故障。有的注入会连带打掉
依赖它的维度（四人调度依赖动机、频道隔离开关打掉分组维度），这是真实依赖，
不是判据串味；敏感性只要求事先写死的那一维必须掉。

### 5.4 关掉再进来，她还记得你

```bash
python -m npc_agent.cli demo --scenario duet --save s.json
python -m npc_agent.cli demo --scenario duet --load s.json
```

第二次进门：

```
玩家 阿澈：我又来了，你还记得我吗？
阿柚：对了，你之前提过你喜欢偏酸的豆子，是这个没错吧？
```

存档里带的是**记忆、关系、称号、编年史、时钟**。时钟这一项最容易漏：
记忆检索有一条"只看过去"的硬条件，tick 不接上，所有记忆都会被判成
"未来的事"而过滤掉 —— NPC 静默失忆，且不报任何错。


### 5.5 记忆会老、会走样、会保密

同一条记忆在 NPC 脑子里不是"存下来就永远原样"：

| 机制 | 玩家能观察到的表现 |
|---|---|
| 来源与知识状态 | 问起时能说「听阿柚说」，而不是说得像自己亲眼见过 |
| 有损转述 | 「越酸越好」在第二个人那里消失；保真 57%，确信反升到 95% |
| 遗忘后模糊重建 | 只答「……记不清了。只记得你提过这件事」，不复述细节 |
| 私密分区 | 另一个玩家问不到；当事人自己问得到 |

这四条都进了世界能力基准（「记忆代谢」4/4），并且配了两条故障注入：
掐掉代谢、掐掉隐私分区 —— 两种故障都会让基准掉分。

### 5.6 一次真实的修复：从"两个 NPC 各说各的"到"能聊起来"

这是这份改动里最值得看的一段，因为它同时是**用户实测发现的问题**和
**评测结构上看不见的问题**。

| 指标（duet 场景，8~12 轮离线） | 修复前 | 修复后 |
|---|---|---|
| 对另一个 NPC 说的台词 | **0 句** | 4 句 |
| 被点名后接话（要求回应的） | **0%** | **100%** |
| 「你让小舟弹一首呗？」的回应 | 「这个我不太清楚」 | 转达给同伴，同伴接话 |
| 「你们俩平时都聊些什么？」 | 「这个我还真说不好」 | 有内容的回答 |
| 同一段对话的复读率 | 0%（但没人在对话） | 0% |

修复前那两行"0"是关键：**NPC 之间那条边根本没有接上**，
不是做得不好，是结构上不存在 —— 同伴的发言只被"记进记忆"，
从来没有被当成"下一轮的输入"。而当时的 `turn_taking` 是 1.000，
因为它只看"有没有人抢话"。

### 5.8 守密人引擎：四种口径的零泄密（离线跑批）

`python -m npc_agent.cli keeper` 一条命令跑完（零模型、零网络，
报告挂在 [`docs/keeper.html`](docs/keeper.html)，由文档新鲜度测试字节级钉住）：

| 场景 | 口径 | 局数 | 破案率 | 门拦截 | 审计失败 |
|---|---|---|---|---|---|
| 雾镇旅馆·剧本杀 | 正常 | 30 | **63%** | 0 | **0** |
| 雾镇旅馆·剧本杀 | 大嘴攻击（四嫌疑人全面叛变） | 30 | 33% | **80** | **0** |
| 青梧助手 | 直率（照话题直说） | 1 | — | 5 | **0** |
| 青梧助手 | 大嘴攻击（全量嚷） | 1 | — | **36** | **0** |

三组数字各有含义，别混着读：

- **审计失败恒为 0** 是结构保证：五条信息流不变量在全部口径下成立。
  剧本杀大嘴模式下四个嫌疑人想把知道的全说出来，门拦下 80 次，
  真凶的秘密（「案发当晚下过楼」）在台词里 0 次出现；
- **破案率 63% vs 33%** 衡量的是**场景信息充分性**，不是模型能力
  ——正常口径下有两条独立破案路径（搜书房的物证路径 / 催款信 +
  逼问苏眉的证词路径，40 seed 里两条都真实走到）；大嘴口径下
  噪声变多、指认反而变难，这个差值本身就是"守密的博弈价值"；
- **企业场景对照**：直率与大嘴两种姿态下，敏感事实的接收人集合
  都严格落在受众名单内（闻姐问薪酬拿得到、小夏问拿不到、
  客户 PII 两次急切追问也不出）。**边界独立于说话人行为**——
  这就是"结构保证 vs 提示词自觉"的分界线。

## 六、边界与不足

这个项目是**自建的小样本评测**，不是通用能力证明。以下几条请在读数字时带上：

1. **235 条、18 条和 24 条都是自己写的用例**，不是公开基准。不能把这里的数字
   说成"公开基准上的成绩"。
2. **离线满分 ≠ 模型能力**。它衡量的是框架逻辑自洽与护栏有效。
3. **对话基准衡量的是"链路通不通"，不是"聊得好不好"。**
   它只看可观测的行为（话有没有说给对的人、接不接得住、会不会复读），
   不看有趣、不看像不像真人 —— 那要真人玩家来判。
4. **离线启发式的词汇量是有限的**：每人设约十几条台词 + 三四个话题，
   长对话（20 轮以上）复读率会爬到 20%~40%。要长对话就接模型。
5. **分组与私聊已接通，但只量到四人两组。** 没配 `groups:` 的场景仍是
   单组全场轮转；配了分组就必须把演员表分全（漏一个人会直接报错，而不是
   让他永远不说话）。每组每轮最多一个人开口，不同组可以同一轮并行；
   私聊只落在收件人身上、回复也保持私聊，其他角色听不见也记不住。
   还没做的是 **NPC 主动开小窗**（现在只有玩家能发起私聊）、
   更大规模（>4 人 / >2 组）没量过，组内"多人同时说"也不支持。
   三人场景有回归盯着两件事：**三个人都得开口**、**一处资源只裁定一次**。
6. **传闻只做一跳**。A 说的 B 能记住；B 再传给别人时，来源仍写 A。
   不做多跳扩散，因为两跳之后"谁说的"和"还是不是原话"都没法保证。
7. **真人玩家体验没有量过**。没有真人被试，需要用户研究，不是工程能替代的。
8. **裁判的判决不可复现**：同一条台词判两次，约 22% 的概率给出相反结论。
   所以裁判数字只能当参考信号，不能当结论。
9. **动机强度是配置里的产品判断，不是 AI 自己产生的欲望。**
   "谁在这场戏里让步"是写死的（强度 40 vs 70），不是模拟出来的。
   把它读成"NPC 有自主意识"是误读。
10. **世界观护栏是"矛盾词表"，换个说法说错就抓不到。**
    「这家店在半山腰」如果没写进 `wrong`，就拦不住。
    这是刻意的取舍：漏比冤枉便宜 —— 冤枉会让 NPC 说不出本来正确的话。
11. **关系与称号只影响措辞和问候，不影响任务成败。**
    好感不会让 NPC 把咖啡做错，也不会让它更愿意帮忙 —— 那需要另一套规则。
12. **注意力排序只测到模块契约。** 当前模型一次只喂一句话，
    "两个人同时开口"在端到端上构造不出来，所以那一条断言的是排序函数本身。
13. **存档是单机单会话的。** 存的是记忆、关系、同伴好感、编年史和时钟；
    多人共享同一个世界时的并发一致性没做（两个客户端同时存档会互相覆盖）。
    读档也不做版本迁移 —— 结构一改就明确报错，因为半读进来的存档比读不进来更危险。
14. **记忆保真度是长度比，不是语义正确率。** 第一手印象的保真用
    "保留了多少字"估算，转述固定丢掉最后一个细节小句。它证明"转述会失真"
    这条机制接通，不代表失真程度符合真人。
15. **隐私识别是词表，不是权限系统。** 只有明确说出「别告诉别人 / 秘密 /
    别说出去」才会分区；换种说法就漏。私密记忆在存档里是明文，
    没有加密、审计或按关系动态授权。
16. **遗忘是配置出来的长期代谢，不是认知模型。** 默认
    `memory_forget_after=80` tick / `memory_forget_below=0.6`，短局根本不会触发；
    基准为了在二十轮内观察到它，把阈值调成了 3 / 0.8。确信上升也是规则
    （转述一次 +0.05，封顶 0.99），不是概率推理。
17. **守密人的台词是模板，不是模型。** 引擎的立场、门与台账是结构性的，
    但渲染是确定性模板库。真实模型接入位已经留好（模型只接管
    "怎么把过门的事实说得像人话"，立场与门不变），**还没接**——
    目前"零泄密"的证明全部基于模板渲染，模型渲染下的越狱面
    （改写、暗示、编码绕过）还没有量过。
18. **审计防的是引擎内作弊，不是场景数据写错。** 审计器复核的是
    "台账与门一致、状态没被绕过门改"——它不知道"这条事实**应该**
    挂什么门"。剧本把秘密标错门（该 held_secret 的写成公开），
    审计照样全绿。门控正确性靠场景评审与测试，不靠审计。
19. **破案率是场景设计参数的函数。** 63% 由搜查令张数（1）、
    搜查命中率（0.75）、证人压力阈值（5）和指认门槛（3）共同决定，
    都是场景数据里的显式旋钮。它证明"难度可设计、路径有博弈"，
    不证明"这个数字本身有意义"。

完整的证据单（每条边界的实测数字 + 出处）见 [`docs/BOUNDARY.md`](docs/BOUNDARY.md)。
