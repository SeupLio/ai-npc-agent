# ai-npc-agent

> 面向游戏场景的**可控** AI NPC 智能体框架 —— 让 NPC 不只是会说，而是真的会玩。

`Python 3.10+` · `MIT` · `零配置可跑` · `可接入 Unity / Godot / Web`

这是一个让游戏 NPC 从"能聊天"走向"能参与世界"的框架。它把语言、决策、动作与世界状态连成一条可验证的链路，并把"什么时候不说话、什么话不能说、说错了怎么记住"这些真正决定体验的边界，做成可测试的结构，而不是交给提示词去祈祷。

---

## 为什么做这个项目

把一个大模型 API 接进游戏，一天就能做出演示；但要做成能上线的玩法，几乎一定会撞上下面这七道坎。这不是凭空列举，而是任何做"活世界"的团队都会遇到的问题：

| 常见痛点        | 玩家的体感        | 本项目的做法                      |
| ----------- | ------------ | --------------------------- |
| 说完话没有行动     | "看着会说，其实不会玩" | 说话和做事走同一条执行路径，每个动作都带回结果     |
| 忘记前面聊过的事    | 人设崩、剧情断裂     | 分层记忆 + 混合检索，重要的记得住，过时的会淡忘   |
| 被问住就顺着跑偏    | 剧透、出戏        | 知识边界与内容红线在工具层拦截，不靠提示词请求     |
| 多人同时说话就乱    | 抢戏、冷场        | 由导演层统一收放发言权，同一时刻只让该说话的人开口   |
| 同一个错误反复犯    | 稳定性差         | 把失败归因写成教训，下一次决策时带上          |
| 两个 NPC 聊不起来 | 各说各的，玩家插不上话  | 对话线程层：接话义务、话题账本、连聊上限        |
| 换一个游戏就要重写   | 架构不可复用       | 世界抽象成统一接口，换世界只写适配器，Agent 不改 |

**我们希望带来的改变**：让"NPC 像不像活的"从演示时的主观印象，变成可复现、可回归、可算账的工程问题。

---

## 它能解决什么问题

- **对话与行动脱节**：NPC 说的话和它做的事走同一条路径，不会出现"说了但没做"的静默失败。
- **记忆不可信**：每条记忆带来源、时间、重要度和知识状态；转述会失真，长期不用会淡忘，被托付的秘密不会进传闻。
- **角色之间没互动**：NPC 之间会互相点名、接话、转达，话题说过就不再复读；玩家也能对某个分组说话，或悄悄说给某一个人。
- **世界观说错**：设定、关系、称号、动机都作为数据参与决策，说错的话在出口被拦下。
- **敏感信息泄露**：守密人引擎把"谁知道什么、什么条件下可以说"做成显式数据与门禁，并留下完整台账供独立审计。
- **上线成本不清楚**：提供 token 计量、延迟分位与成本推算，回答"一万个玩家聊十轮要花多少"。
- **换场景成本高**：角色与场景都是 YAML 配置，加一个角色或场景不用改代码。

## 原理概览

一次 NPC 交互可以理解为一个闭环：

```
玩家输入 / 世界事件
        ↓
   感知与理解 ──→ 分层记忆（当前对话 / 长期事实 / 经验教训）
        ↓
     规划决策 ──→ 导演层决定谁开口、对谁说
        ↓
   工具执行 ──→ 说话、移动、制作、给予……均作为工具调用
        ↓
   边界检查 ──→ 出戏 / 剧透 / 设定错误 / 隐私 在出口拦截
        ↓
     结果写回 ──→ 世界状态改变，失败进入反思
```

三个设计取舍贯穿整个框架：

1. **要的是可控，不是能力上限。** 什么时候**不说话**、什么话**不能说**、失败如何归因，被放在工具层，因此能被测试钉住。
2. **演示能跑 ≠ 可评测。** 默认路径是确定性的、无需联网和 API key；模型是可插拔的上层。这样同一份输入两次跑出同样结果，"改动有没有变好"才有答案。
3. **边界独立于说话人。** 守密人引擎把信息流控制从提示词层下沉到引擎层：知识是显式数据，台词在渲染时只拼装过门成功的事实，被拦下的尝试也进台账，最后由独立审计器复核。因此"零泄密"是有证据的结论，而不是一句承诺。同一套原语既跑剧本杀对抗守密，也跑企业助手的合规边界。

## 快速开始

需要 Python 3.10+（持续集成覆盖 3.10 / 3.11 / 3.12）。**不需要 API key，也不需要联网。**

```bash
pip install -r requirements.txt
```

**最直观的入口：自测控制台**

```bash
python -m npc_agent.cli studio
```

浏览器打开一个本地网页（仅绑定 `127.0.0.1`），四个页签：对话演示、跑评测、变异测试、报告门户。页面直接调用框架本身，数字与命令行一致。

**看几个现成场景**

```bash
python -m npc_agent.cli demo --scenario duet        # 两个 NPC 协作，互相点名接话
python -m npc_agent.cli demo --scenario trio        # 三个 NPC 同场
python -m npc_agent.cli demo --scenario quartet     # 四人两组，分组并行与私聊
python -m npc_agent.cli chat --scenario tutorial    # 自己上手对话
```

**关掉再进来，她还认得你**

```bash
python -m npc_agent.cli demo --scenario duet --save s.json
python -m npc_agent.cli demo --scenario duet --load s.json
```

存档包含记忆、关系、称号、编年史和时钟。

**接进你的游戏引擎（Unity / Godot / Web）**

```bash
python -m npc_agent.cli serve --port 8080
```

起一个 HTTP API：建会话 → 玩家发言 → 拿 NPC 台词与动作，带事件流和按玩家存档。三端最小样例见 `docs/GAME_SERVER.md`。

**上线前算成本账**

```bash
python -m npc_agent.cli cost --scenario duet --repeats 5
```

给出延迟分位、真实 token 用量与每 100 轮成本推算。离线读数是框架自身的开销，接上模型再跑一次的差值即模型开销。

**跑评测**

```bash
python -m npc_agent.cli eval
python -m npc_agent.eval.dialogue_bench
python -m npc_agent.cli keeper          # 守密人引擎可验证信息流跑批
python -m pytest tests
```

**接上真实模型**（任何 OpenAI 兼容端点均可；不配置则全部走离线路径）

```bash
export NPC_AGENT_PROVIDER=openai-compat
export NPC_AGENT_BASE_URL=https://<你的端点>/v1
export NPC_AGENT_API_KEY=<你的 key>
export NPC_AGENT_MODEL=<模型名>
```

## 效果概览

> 请先看这一句：下面的离线读数衡量的是**框架逻辑与护栏是否有效**，不是"这个 NPC 有多聪明"。离线路径不调用任何模型。

- **回归基线**：235 条自建用例，覆盖任务、工具、记忆、人设、安全、发言权六个维度，全部通过。
- **多 NPC 对话基准**：18 条，覆盖接话、转达、有依据的回答、不复读、印象流动、发言权，全部通过。
- **世界能力基准**：24 条，覆盖设定一致性、关系与称号、动机事件、注意力、记忆延续、记忆代谢、多 NPC 同场、分组与私聊，全部通过。
- **守密人引擎**：62 局跑批、四种口径，含"说话人全面叛变"攻击，审计失败为 0。
- **测试**：1376 通过、1 跳过（该用例需真实 Minecraft 服务端）。
- **真实模型跑批**：在 228 条用例上达到 227/228，但已触及用例集天花板，报告中也明确标注为"已饱和"。

三套基准都配有敏感性检验：向框架注入一个故意的缺陷，评测必须掉分，用来证明分数不是"判据从不报警"造成的。

**需要如实说明的边界**：这些用例是项目自建的小样本，不是公开基准；离线满分不代表模型能力；对话基准衡量的是"链路通不通"，不是"聊得好不好"。长对话（20 轮以上）的离线词汇量有限，建议接模型。完整证据单见 `docs/BOUNDARY.md`。
